- 원인(VERIFIED 소스): reserve_decode는 헤더 (w,h)를 rgba_bytes로 바꿔 예약한 뒤 크기를 버렸다.
  decode_image_to_canvas는 헤더 경로에서 r.authorizes(actual)만 검사했다. 그래서 일반 용량 규칙
  (actual ≤ reserved)만 남고, 이미지 크기 동일성은 검사하지 않았다.
- 재현(VERIFIED, rust/before-dimension-repro.json): 이전 판정을 그대로 옮긴 모델로 실행했다.
  · 승인되어 단언이 실패한 3건:
    - 100×100 헤더에 90×90
    - 100×40에 40×100(같은 픽셀 수)
    - 200×20에 100×40(같은 RGBA bytes)
  · 기존 용량 검사로 거절된 2건: 더 넓은 경우, 더 높은 경우
  · 정확히 같은 크기는 승인했다.
  이는 함수 수준의 재현이며, 실제 decoder가 이런 결과를 냈다는 주장이 아니다.
- 도달성(VERIFIED 시험 + 소스): image 0.25.10은 decoder.dimensions()로 버퍼를 만들고 방향 변환을 적용하지 않는다.
  후보도 apply_orientation을 쓰지 않는다. 기존 corpus·손상 시험과 새 real_supported_images 시험에서
  헤더 = DynamicImage = RGBA였다. 정상적으로 크기를 바꾸는 변환은 없으므로 정확한 일치가 생산자 계약이다(INFERRED).
- 심각도: 계약 무결성 결함(P2). 현재 decoder에서는 실행 중 발생을 관찰하지 못했다.
- 수정(격리 RHWP, 2파일):
  · canvas_rgba.rs: DimensionMismatch, check_decoded_dimensions, DecodedRefusal{Mismatch, Capacity, Reserve}, authorize_decoded
    (헤더 예약과 크기를 함께 받아 Canvas 할당 전에 "크기 동일성 → bytes 승인"을 하고, 헤더가 없으면 "사후 예약 → bytes 승인"을 한다).
  · web_canvas.rs: reserve_decode가 (헤더 크기, 예약)을 돌려준다. decoded_canvas가 이를 decode_image_to_canvas로 넘긴다.

    · Mismatch는 Decoded::Rejected(job ERROR, 음성 entry 없음, Canvas 없음, 예약 해제)이고, dimensionMismatches를 센다.
    · 기존 사후 예약 closure와 Refused/Oversize 분류는 그대로다.
  · surface_cache.rs의 일반 예약 계약은 바꾸지 않았다(actual ≤ reserved, 더 작은 할당은 실제 크기로 계상).

    할당 0, reserved 0, 오류 0, 기존 공유 backing 보존(dispose 0, unique 256 유지).
