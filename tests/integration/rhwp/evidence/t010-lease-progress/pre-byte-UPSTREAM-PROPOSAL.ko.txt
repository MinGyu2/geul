T010 다음 최소 실험 제안 — 아직 구현하지 않음

관측 근거(VERIFIED): 최종 native D4 후보24쪽 HWP group-start p95=372ms. 해당 동일 표본에서 full pollRenderJob128ms 및 추가 poll7ms, 후속 frame 잔차174ms, key→input45ms가 관측됐다. pinned 쪽 p95=84ms의 표본은 기존 patch API5ms였다. 이는 순수 scheduler patch의 인과 효과가 아니라 다른 adapter/render 구성 비교다.

현 소스: 시험 adapter는 항상 beginRenderJob(Full)을 쓰고 RhwpEditorSession의 기존 paintedSummary/repaintInPlace 경로를 우회한다. 내부 Replay::Patch와 render_compat_replay는 이미 있지만 compat PENDING은 예외로 반환되며 동기 host 완료 계약에 그대로 넣으면 안전하지 않다.

제안: 먼저 시험용 명시적 patch-job begin/poll 요청과 기존 damage 요약의 연결만 설계한다. renderer/tree/layout 전체 재작성은 하지 않는다. Full과 Patch 요청 identity(캔버스/page/scale/replay/bounds/generation/model revision), 불완전 frame 비게시, 보유 lease 수명, 예산, 늦은 결과 차단을 유지한다. 자동으로 기존 void API를 COMPLETE로 간주하지 않는다.

검증:24쪽 HWP 한 문서에서 dirty-band와 Full을 동일 key/RAF 계약으로 비교하고, body/cell/multi-section native Undo/Redo RGBA 및 기존 ownership52/scheduler54/native53+11 회귀를 통과한 뒤 네 문서 공식 D4를 재측정한다. 이벤트 dispatch와 RAF 잔차가 여전히 크면 OS/WebKit/React main-thread trace를 따로 취한다. API 경과를 순수 layout CPU로 부르지 않는다.

기준 유지: group-start p95<=50ms, Undo<=1500ms, native keydown→revision 관찰 RAF→추가2RAF. 소유권·픽셀·보존을 희생하지 않는다. production Undo/Redo와 T010/T011 상태는 바꾸지 않는다.
