T010 Rust 1.99 strict Clippy 호환성 계약

범위와 불변 경계
고정 RHWP에서 내보낸 기존 격리 후보 위의 호환 패치다. external/rhwp, public/rhwp, 생산 코드,
양 gitlink, Cargo.lock/manifest/rust-toolchain.toml, 과거 증거/anchor/보안 예외는 변경하지 않는다.
설치된 Nix Rust1.99.0 및 wasm32 target만 사용한다. 모든 Cargo 빌드/검사/시험은 locked+offline,
CARGO_NET_OFFLINE=true, CARGO_INCREMENTAL=0, CARGO_BUILD_JOBS=2와 기존 target/rhwp-wasm 하나다.
신규 설치/다운로드/공유 캐시 삭제/기존 scratch 삭제/production UndoRedo 활성화/push는 금지다.

필수 strict gate
host 및 release wasm32의 cargo clippy --locked --offline --workspace --lib --message-format=json -- -D warnings,
각 타깃의 -p rhwp --lib --no-deps 변형을 모두 실제 exit0으로 완료해야 한다.
최근 수정 파일의 진단0은 이 조건을 대체하지 않는다. 새로 드러난 workspace 오류도 해결해야 한다.
전역 allow/경고 수준 완화/lock 변경/멤버 제외/검사 목적의 feature 제외는 허용하지 않는다.

최소 교정의 의미
chunks_exact: 같은 폭의 as_chunks/as_chunks_mut().0을 iter/iter_mut로 순회한다.
원래 무시한 tail을 동일하게 무시하며 바이트 순서·갯수·가변 참조의 독점 소유를 유지한다.
암호 AES는 기존 패딩 및 bit feedback/truncate를 유지한다. DES는 완전8바이트만 처리하며 tail 미변경,
공개 HWP3 입력의 정렬 검증은 그대로다. 보장된 배열 변환의 불가능한 expect만 제거한다.
fill: bool/정수/f64 Copy 원소에 같은 값을 대입한다. 부수 효과나 새 초기화 정책을 도입하지 않는다.
sort: stable sort_by_key(Reverse)로 내림차순·동률의 삽입순서를 보존한다.
checked_div: usize의 count0만 None이다. 좌표·기존 checked arithmetic 검증 뒤 source 측정을 생략하는
0회 경로를 보존한다. 정상 회수의 노드·byte budget과 거부는 유지한다.
counter: 기준 index+enumerate offset으로 같은 Unicode char를 검사한다. empty/범위 초과/usizeMAX를 시험한다.
drain: 동일 children Vec을 mem::take로 넘기고 임시 parent를 비운다. 부모는 그 뒤 사용 없이 drop되며,
수신 함수는 원소와 순서만 소비한다. 메모리 상한이나 장기 캐시 정책을 변경하지 않는다.
match guard: 차트의 기존 세 조건을 동일 순서로 평가한다. 실패 시 기존 no-op와 동일한 wildcard 처리다.

보안 민감 동등성
기존 HWP5 외부 벡터 및 roundtrip을 유지한다. 수정 전 코드에서 측정한 198개 입력의 AES 결과 digest,
DES known-answer와 길이0..33의 완전블록/부분tail, 실제 HWP3/HWPX 비밀번호 거부/재암호화를 검사한다.
HWPX는 재작성되는 암호 manifest 메타데이터와 payload를 구분한다. 항목 목록과 모든 비-manifest bytes는 같아야 한다.
알고리즘/키 유도/암호 의존/입력 검증을 변경하지 않는다. 상수 시간의 형식 검증을 주장하지 않는다.

런타임·렌더
Outcome::record/Job::finish/mark_error/mark_limit/memoize/record_prepared/prepare_payload 구현은 그대로다.
preparation/render_job/web_canvas/surface_cache/canvas_rgba/wasm_api 6파일의 바이트를 직전 후보와 대조한다.
첫 terminal 이유, 준비 단계·양자256/4·32MiB/64MiB·key256·deadline·원자 publication·기본 off를 유지한다.
변경된 후보에 기존 양 브라우저 hardening10+3/runtime49/ownership52/scheduler73 및 RGBA42를 적용한다.
화학7쪽(14/15/16/19/20/21/23), 같은 원본/scale/DPR/extent/cold-warm/3회를 유지하고 빈 reference를 거부한다.
기준 eaa88f65…의 실제 bytes를 확인해 재사용한다. 원래 ae34 oracle의 직접 비교는 UNVERIFIED다.

신원과 증거
새 candidate identity와 완전/compatibility patch를 별도 경로에 작성한다. src-only 과거 digest와
새 workspace digest를 구분한다. 새 digest는 crypto/chart crate·선언된 tools/bindings와 Cargo 메타데이터도 포함한다.
두 patch를 고정 source와 직전 후보에 각각 독립 적용하여 동일 workspace 입력 digest를 요구한다.
실제 WASM/JS/d.ts/ENGINE bytes 및 커밋된 patch bytes를 측정한다. 기대 hash 복사는 관찰이 아니다.
최종 commit 이후 실제 HEAD의 민감정보/Gitleaks 전체 이력 검사를 다시 실행하고 외부 새 폴더에 보존한다.
커밋 자신을 포함한 이력 결과를 그 커밋에 넣을 수 없으므로 postcommit 산출물은 최종 응답과 재현 절차로 연결한다.

공식 상태와 별도 승인
이 별도 호환 작업이 완료되어도 T010 INCOMPLETE, native 승인 PENDING, D4 FAIL,
production UndoRedo NO-GO, T011 NOT STARTED, 정책2636a650 PENDING_APPROVAL은 바뀌지 않는다.
과거 native attempt3 FAIL/원인 UNVERIFIED도 유지한다. Clippy 성공은 native 승인/공식 D4 성능 근거가 아니다.
