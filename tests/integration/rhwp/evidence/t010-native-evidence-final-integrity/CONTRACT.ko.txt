T010 native D1 최종 무결성 수용 계약

분류: VERIFIED는 소스·바이트·실행으로 확인, INFERRED는 근거의 해석, UNVERIFIED는 미확인이다.
이 문서는 공식 D4 재측정이나 T010 승인 문서가 아니다.

1. 권위와 버전
권위 있는 정의는 ownership-poc/native_d1_result.py의 DEPENDENCY_MANIFESTS, FIXTURE_SHA256,
PINNED_FIXTURES, RHWP_REVISION, SCHEMA, TRUST_ANCHOR이다. wrapper는 같은 모듈을 사용한다.
결과 JSON은 기대 집합·기대 신원·manifest 버전을 결정하지 못한다. manifest-v3.json은 설명용 파생 스냅샷이다.
새 wrapper는 manifest 3과 verdict schema 3을 사용한다. lifecycle producer schema는 기존 2를 유지한다.
manifest 1(18개), 2(22개)의 이름·정책은 변경하지 않았다. 명시적으로 선택한 과거 계약은 기존 schema 2
재판정을 반환한다. 과거 기록 자체의 schema 1/2는 수정하지 않는다. 현재 exit_code는 schema 3만 수용한다.
과거 계약 PASS는 schema 3 또는 manifest 3의 실제 실행 PASS라는 뜻이 아니다.

2. 의존 집합
manifest 3은 v2 전체에 아래 9개를 추가한 31개다. 수는 소스 읽기·실행 관계 확인 후 계산했다.
- 이 디렉터리 run-native.py: 실제 실행·증거 기록·관찰·판정 wrapper.
- package.json: vite.config.ts의 버전 읽기 및 Node 패키지 범위.
- tsconfig.json: Vite의 TS/TSX 변환 설정(설치된 Vite loadTsconfigJsonForFile 경로 확인).
- public/rhwp/rhwp.js, public/rhwp/rhwp_bg.wasm: 두 생성기의 실제 실행 엔진.
- public/rhwp/BUILD.json: basic 생성기가 rhwpCommit 보고를 위해 직접 읽음.
- tests/integration/rhwp/cache-concurrency/fixtures.mjs: ownership 생성기가 svg를 import.
- external/rhwp/samples/rnote/연구노트(화학).hwp: Vite 및 D1 실제 문서 입력.
- external/rhwp/samples/issue6031/3249937_asset_management_rules.hwpx: D1 실제 문서 입력.
전체 경로 목록과 v2 항목의 역할은 manifest-v3.json에 있다. 단언 개수로 의존 완전성을 추론하지 않는다.

이름 집합은 전후 각각 manifest와 정확히 같아야 한다. 누락·추가·비정규 이름·쌍 목록 중복은 거부한다.
소문자 64자리 16진 문자열만 SHA-256으로 수용한다. None·대문자·잘못된 타입·길이는 실패다.
읽기 실패·파일 부재는 digest None으로 실패한다. 필수 파일 하나라도 전후 값이 다르면 실패다.
wrapper는 Vite를 시작하기 전에 preflight를 하고, 실행 후 전체 집합을 다시 계산한다.
서브모듈은 superproject ls-files 재귀 동작에 기대지 않는다. index gitlink 모드·고정 revision, checkout HEAD,
두 고정 revision blob의 해시 및 작업 파일의 전체 바이트를 별도로 확인한다. 누락·변경·다른 revision은 실패다.
고정 샘플은 dependency map에서도 독립 FIXTURE_SHA256과 대조한다.

3. frontend 집계 정책
기존 tree:src는 Git 추적 경로의 작업 바이트를 path NUL digest LF로 정렬 집계한다.
v3에서는 src의 실제 파일·symlink 집합이 Git 추적 집합과 다르면 실패한다. ignored 파일도 예외가 아니다.
추적 symlink도 거부한다. Vite의 암묵적 .env, .env.local, .env.development, .env.development.local이
있어도 실패한다. 미추적 파일이 Vite의 import 해석에 영향을 줄 수 있기 때문이다.
이 정책은 미추적 파일까지 tree digest가 덮는다고 주장하지 않는다. 현재 frontend 93개 추적 파일을 확인했다.
검사는 전후 스냅샷이다. 실행 중 잠깐 바뀌었다 복원되는 공격의 완전한 감시가 아니다.

4. 네 문서 신원
순서와 정확한 이름: basic-ko.hwp, basic-ko.hwpx, 연구노트(화학).hwp,
3249937_asset_management_rules.hwpx. 정확히 네 개가 필요하다.
각 sourceSha256은 필수 소문자 SHA-256이며 독립 FIXTURE_SHA256과 일치해야 한다.
기대값은 결과나 결과의 expected 필드에서 읽지 않는다. 세부 값·실제 계산은 fixture-verification.json 참조.
기본 두 문서는 커밋된 생성기와 public 엔진으로 서로 다른 임시 디렉터리에서 독립 Node 프로세스 3회 생성해
전체 바이트 해시 일치를 확인했다. HWPX ZIP 시각은 모두 1980-01-01 00:00:00이다.
이는 확인한 입력·환경의 결정성 증거이며 모든 미래 도구·엔진 버전의 결정성을 보장하지 않는다.
wrapper도 매 실행 전에 독립 생성하여 계약값과 대조한다. 공식 두 샘플은 고정 submodule blob과 직접 대조한다.
실제 하네스의 임시 기본 문서는 producer가 삭제한다. wrapper의 독립 생성과 보고 digest 대조는 수행하지만,
하네스의 열린 모든 파일 바이트를 별도 관찰기로 다시 읽었다고 주장하지 않는다. 공식 샘플은 같은 경로를 전후 읽는다.

5. lifecycle schema 2의 구조 검증
최상위 필드: schema, attempt, observer, samples, observerError, observerStopped, loadAverage,
cpuCount, processes, events, leftAtEnd. 누락·추가는 lifecycle-evidence 실패다.
schema는 정확한 int 2, attempt는 양의 정확한 int이며 wrapper 호출의 attempt와 같아야 한다.
호출자가 독립 attempt를 전달하지 않으면 실패한다. 이전 wrapper는 새 CURRENT_MANIFEST를 동적으로 읽더라도
이 인자를 전달하지 않아 v3 PASS를 받을 수 없다. 과거 계약의 명시적 재판정은 영향을 받지 않는다.
observer 설명은 기존 producer의 고정 문자열이다. samples와 cpuCount는 양의 정확한 int다.
loadAverage는 start/end 각 세 개의 유한한 음수 아닌 수다.
observerError는 필수이며 None이어야 한다. 문자열 오류 또는 observerStopped가 True가 아니면 observer-failure와
증거 결손(evidence-write)으로 실패한다. 누락된 lifecycle은 evidence-write로 구분한다.

processes는 객체 목록이며 각 행은 pid, comm, ppid, pgid, firstSeen, lastSeen, states와 선택 gone만 갖는다.
pid·pgid는 양의 int, ppid는 음수 아닌 int다. bool·float·문자열·None은 PID로 수용하지 않는다.
comm은 1–15자 문자열이다. PID 중복은 금지한다(관찰기는 사라진 PID를 재사용하지 않는 설계).
states는 알려진 /proc 상태 문자와 양의 정확한 int 카운터의 비어 있지 않은 map이며 합은 samples 이하이다.
firstSeen <= lastSeen <= gone이고 시간은 유한한 음수 아닌 int/float다. bool, NaN, Infinity,
음수, 문자열, 너무 큰 정수도 거절한다. gone이 없는 소유 행은 최종 생존으로 실패한다.
leftAtEnd는 gone 없는 행과 정확히 같아야 하며 최종적으로 빈 list여야 한다. geul을 한 번은 관찰해야 한다.

이벤트는 appeared/reparented/gone/harness-start/harness-exit의 실제 필드 집합만 허용한다.
PID·comm·부모 전이·firstSeen/gone 시각·최종 ppid는 행과 일치해야 한다. 각 PID의 appeared는 한 번,
그 뒤 부모 전이와 선택 gone이 온다. PID별 시간과 harness 시작/종료 시간은 역전되면 안 된다.
harness-exit 코드는 실제 subprocess 종료와 일치해야 한다. 서로 다른 thread가 append한 전체 이벤트 목록에
일괄 시간 정렬을 요구하지 않는다. 앱이 driver보다 먼저 끝나거나 서로 다른 snapshot을 갖는 것은 정상이다.
종료된 geul 관찰, 빈 driver-stop snapshot, snapshot 사이에 사라진 프로세스는 수용한다.
구조 결함(lifecycle-evidence), 관찰기 실패(observer-failure), 최종 생존(lifecycle)을 구분한다.

6. 기존 보장과 종료
39개 단언·24개 exact RGBA 참조와 기존 cleanup 세 단계, teardown 11개 필드, DELETE ok,
driverKilled 정확히 False, driverExit 정확한 int 0 또는 -SIGTERM, 최종 소유 프로세스 없음은 유지한다.
SIGKILL은 언제나 거부한다. -SIGTERM 수용은 기존 INFERRED 정책이며 이번 실제 성공은 모두 exit 0이다.
strict JSON의 중복 key와 비유한 상수 거부, 기록 실패의 비정상 종료도 유지한다.
exit_code의 0은 정확한 int harness_exit 0, dict verdict, 정확한 int SCHEMA(3), 정확한 문자열 PASS,
빈 list failures와 categories가 모두 필요하다. 3.0, 2.0, 문자열, bool, None, schema 없음·미지원은 거부한다.
하네스 1–255는 보존하며 그 외 실패는 3이다. 과거 schema 2 PASS를 현재 helper의 성공으로 바꾸지 않는다.

7. 신뢰 경계
후보 WASM/JS/d.ts/ENGINE.json은 기존 TRUST_ANCHOR와 그 고정 파일 해시를 유지한다.
기준은 git show HEAD:로 읽는다. 후보 ENGINE.json·명령 인자·결과·의존 map 자체는 신뢰 출처가 아니다.
소스 신원: Git 경로 및 바이트와 보호 경로 비교로 확인한 범위다.
실행 안정성: 전후 digest 동일성이다. 안정하다는 이유만으로 그 바이트를 진짜라고 인증하지 않는다.
독립 진위 확인: 고정 후보 anchor와 고정 sample blob, 재생성한 fixture의 범위다.
환경 출처: node_modules, Python/Node 캐시·실행기, 시스템 라이브러리, WebKitGTK, 드라이버, 폰트,
외부 환경 변수·OS는 이 manifest의 완전 인증 범위 밖이다. 필요한 도구는 실제 실행하였지만 독립 서명하지 않았다.
저장소 anchor는 외부 서명이나 전체 공급망 증명이 아니다. 완전 재현성·RSS 안정성을 주장하지 않는다.
