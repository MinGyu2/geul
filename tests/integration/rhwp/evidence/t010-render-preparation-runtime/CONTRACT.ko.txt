T010 격리 Full 준비 실행 계약

상태 표기의 의미
VERIFIED: 해당 소스·바이트·현재 실행으로 확인. INFERRED: 확인한 근거의 해석.
UNVERIFIED: 현재 실행으로 확인하지 않은 주장. 실행 결과는 REPORT와 개별 증거를 참조한다.
이 문서는 공식 D4, RSS 또는 production Undo/Redo 승인 계약이 아니다.

도달 가능한 실행 경계
실험 export setRendererPreparationEnabled(true)를 명시적으로 호출한 모듈의 비동기 Full job만
Preparing → ResourcesReady → FullReplay → Terminal을 사용한다. gate 기본값은 false다.
기존 외부 poll 결과 PENDING/COMPLETE/CANCELED/ERROR/RESOURCE_LIMIT은 그대로다.
ResourcesReady 진입도 반드시 PENDING을 반환하며 scratch는 아직 없다. 다음 poll에서만 replay한다.
Filtered, Patch 자체 replay, Legacy, HeaderFooter 및 기존 동기 호환 API는 기존 경로를 유지한다.
명시적 비동기 Full fallback은 Full로서 준비한다. 지원하지 않는 variant를 준비했다고 표시하지 않는다.
기존 52/73/41 브라우저 계약은 gate off 호환 회귀다. gate on 실제 새 경계는 별도 runtime 계약 1이다.
설정 변경은 모든 진행 job을 취소한다. production adapter와 public 엔진은 변경하지 않는다.

트리와 요청 신원
이미 반환된 owned PageLayerTree 하나를 job으로 이동한다. 매 poll마다 rebuild하지 않는다.
문서 owner/job ID/page/replay/scale/target token은 기존 job이 보유하며 모델 신원은 별도로 비교한다.
core cache invalidation의 checked generation, document epoch, 모든 section revision, DPI 비트,
image epoch, Screen 출력옵션, fallback font를 snapshot으로 보유한다. revision 4096개 또는 fallback
4096바이트 초과와 generation overflow는 거부한다. 외부 font 환경 변경은 기존 API invalidation도 유지한다.
취소/종료 후에는 이 신원을 다시 사용할 수 없다. target token만으로 모델 신원을 대신하지 않는다.

payload_estimate()는 관찰용 하한 추정이다. 새 admission에는 사용하지 않는다.
Canvas가 사용하지 않는 arena intern cache, glyph 대안, group provenance만 owned 복사에서 제거한다.
원래 text variant scope를 먼저 검증하고 필수 text_sources와 op의 source 연결은 보존·계상한다.
Canvas 최종 renderer의 검증도 그대로다. 문서 캐시 자체는 바꾸지 않는다.
지원 projection은 Box inline 크기, Vec 실제 capacity×요소크기, String capacity, 모든 중첩 payload,
text style 배열/문자열, gradient, equation layout 등을 checked arithmetic으로 계상한다.
private map/font 소유를 정확히 계상할 수 없는 supplemental metrics snapshot은 RESOURCE_LIMIT이다.
이는 명시적 제한이며 모든 미래 PageLayerTree variant의 무조건 수용을 약속하지 않는다.
깊이 64, 방문 node/op/equation 항목 65,536 상한도 admission 조건이다.

job당 32 MiB, 모듈 전체 64 MiB의 retained preparation 예약을 강제한다. tree·신원·변환 memo를
같은 Rc 예약으로 소유하고 마지막 owner의 Drop에서 해제한다. cursor/key/memo 고정 관리영역은
job당 128 KiB를 먼저 계상한다. 기존 최대 job 8개와 별개로 전체 64 MiB를 초과할 수 없다.
변환 payload capacity도 예약 후 보존한다. 실패 시 계속 보유하거나 PENDING 루프를 돌지 않는다.
이는 새로 도입한 장기 보존 영역의 유한 bound다. 기존 문서 캐시, 순간 tree construction·decoder
작업 메모리, allocator bookkeeping, JS/DOM heap, 시스템 라이브러리와 전체 RSS 상한은 아니다.

cursor와 실제 drawable 신원
ResourceArena 목록이 아니라 immutable Canvas projection의 실제 PaintOp를 DFS cursor로 방문한다.
poll당 cursor step 256회, Image/PageBackground/RawSvg operation 시도 4회 중 먼저 닿는 bound에서 반환한다.
하나의 synchronous tree build/검증/hash/decode/변환/replay를 CPU 선점하는 것은 아니다.
Image와 PageBackground의 watermark 변환, RawSvg 단일 data URL 또는 bbox wrap 변환은
준비와 replay가 공유하는 resolver를 사용한다. 실제 drawable key는 기존 ImageKey::of(해소된 바이트)다.
memo recipe는 원본 ImageKey+operation+bbox 비트이며 drawable key를 대신하지 않는다.
crop/회전은 같은 drawable의 draw geometry다. 변환 바이트가 다르면 별도 drawable key다.
Equation은 Canvas vector/text, pattern은 작은 draw-scoped tile Canvas여서 별도 image lease가 아니다.
실제 browser/decoded 자원을 소유하지 못하면 ready key를 기록하지 않는다.
완료된 op는 cursor를 진전시킨다. pending op만 현재 위치에서 대기하며 이미 준비된 key는 decode하지 않는다.
새 quantum continuation은 기존 coalesced completion 경로에 합쳐 한 번의 알림으로 예약한다.
실제 live Preparing/Ready job이 있고 I/O 대기가 아닐 때만 깨운다. 자기 실행 무한 RAF/timer는 없다.
기존 250ms expiry timer 및 약 15초 deadline은 유지한다.

lease와 종료
기존 Rc<SharedBacking>, weak registry, cache/job 공유 소유, 마지막 owner의 단 한 번 disposal,
resident/nonresident unique byte accounting, reservation commit 실패 처리를 그대로 사용한다.
준비된 decoded lease는 replay가 직접 참조한다. 다른 job의 cache eviction 후에도 backing은 유효하다.
압력 정책이 준비 lease까지 회수해야 한다면 해당 준비 job을 RESOURCE_LIMIT으로 종료한다.
필수 lease를 몰래 없애고 Ready라고 주장하거나 무한 재decode하지 않는다.
combined prepared key/memo 각 256개 상한이며 257번째 필수 drawable은 bounded refusal이다.
기존 gate off 300개 draw-scoped 호환 동작을 새 경로의 지원이라고 표시하지 않는다.
기존 browser pool 256, pending 2, estimated 256MiB, URL32MiB, 단일 decoded96MiB,
decoded cache256MiB/256, browser cache64MiB/256, scratch/backup 각각64MiB는 올리지 않았다.

모든 실제 poll 반환 전 취소·deadline·모델·target 상태를 확인한다. Ready 다음 poll과 scratch replay 후,
backup 후 publication 직전에도 검증한다. 중간 frame은 게시하지 않는다. 기존 scratch→backup→drawImage 및
오류시 putImageData 복원 경로를 유지한다. JS callback으로 인위적 오류를 주입한 시험은 실제 장애와 구분한다.
종료는 tree/cursor/memo/예약/decoded와 browser lease/target을 해제하며 반복 terminal poll은 멱등이다.
close/trim/budget 축소/동일 target 교체/늦은 이미지 완료가 stale publication을 허용하지 않는다.

브라우저 증거 계약
새 runner는 결과의 자체 PASS만 믿지 않고 evidence_contract.py의 정확한 시험 이름/순서와 전이를 확인한다.
실제 다중 poll, retained key/bytes, Ready PENDING에서 12 key와 replay0, 최종 replay1/decode12,
quantum 차이, 비유한 시간과 잘못된 계수기 거부, 최종 unique/reserved/preparation bytes0이 필요하다.
chemical fixture는 기존 독립 FIXTURE_SHA256과 대조한다. 7페이지×cold/warm×3회=42 RGBA 비교를
브라우저별 수행하며 warm 21개는 기존 행렬이다. 동일 source/페이지/scale/DPR/extent에서 직접 픽셀 비교한다.
reference nonwhite가 100 미만인 빈 결과는 거부한다. 합성 PNG/SVG와 공식 OLE/배경 문서는 추가 경로 증거다.
runner는 추가 고정 sample도 고정 git blob과 대조하며 실제 실행 JS/WASM·하네스·입력의 전후 해시를 보존한다.
전후 안정성은 source authenticity 또는 전 과정 변조 감시와 다르다.

신뢰와 공식 gate
이전 native schema3/manifest3/TRUST_ANCHOR와 후보 바이트는 변경하지 않는다.
새 실행물은 별도의 committed candidate-identity.json 및 pinned anchor-file hash를 가진 native 계약4로만 수용한다.
새 native 계약은 기존 strict D1의 39개 단언/24 RGBA/4 fixture/typed teardown/lifecycle/strict JSON을 재사용한다.
manifest4는 기존 v3 전체와 실제 새 wrapper/판정기/Vite설정/새 anchor/새 engine-gates를 추가한다.
결과가 mandatory set이나 기대 candidate를 고를 수 없다. 이전 wrapper/gates는 상속 계약 출처로 유지한다.
새 Vite transform은 session의 실험 opt-in과 poll 통계 관찰만 추가한다. native producer 자체는 바꾸지 않는다.
새 관찰기는 bounded witness 12개와 aggregate counter로 실제 Ready 반환과 replay를 보존한다.
이 anchor는 저장소 내부 신뢰 계약이며 독립 서명이나 공급망 전체 인증이 아니다.
시스템 library/node_modules/폰트/브라우저/toolchain의 완전 provenance와 RSS 안정성은 주장하지 않는다.
기존 보안 정책 편차 2636a650은 PENDING_APPROVAL이다. 새 allowlist 확대는 허용하지 않는다.
공식 T010 INCOMPLETE, D1/D3/D5 historical PASS, D2/RSS INCONCLUSIVE, D4 FAIL,
production RHWP Undo/Redo NO-GO, T011 NOT STARTED는 별도 승인 없이 바뀌지 않는다.
