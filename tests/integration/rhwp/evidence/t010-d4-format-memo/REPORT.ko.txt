T010 D4 — 본문 편집 쪽 나눔의 format 재사용(rhwp 격리 patch, 2026-10-28)

범주: VERIFIED=이번 실행·소스, INFERRED=해석, UNVERIFIED=입증 못함. 제품 WASM·gitlink는 바꾸지 않았다(격리 export + 검토용 patch).

1. 원인(VERIFIED, native release, 후보 0cb73f70 소스와 바이트 동일한 export)
- 자산 규칙 HWPX(60쪽, 구역 0에 593문단)에서 본문 글자 하나: paginate 14.8 ms 중 조판 14.3, 그 안 텍스트 문단 루프 12.8 ms
  (RHWP_2424_PROFILE). insertText의 문서 변경 자체는 0.2 ms(batch로 분리). 본문 편집은 dirty 구역의 모든 문단을 다시 format한다.

2. 교정(patch upstream-rhwp-format-memo-incremental.patch, 커밋본 sha256 abf438623d1c3a2e6d6425fb4364ad2385238e5d40b35e35b87b802cbf16d32a —
   git diff 원문 41c376a5…에서 빈 문맥 줄 표기만 정리, 재현 동일: patch-format-normalization.json)
- 새 모듈 renderer/typeset/format_memo.rs: 본문 흐름의 문단 format 결과를 패스 사이에 재사용한다. 다음이 모두 같을 때만(fail closed):
  문단 dirty 아님(기존 측정 캐시와 같은 dirty 추적), 구역 키(배율, 레이아웃 프로파일, 통짜 사다리 판정, 용지/쪽 어울림 증거, 스타일
  세대 번호, 문단 수), 문단 키(단 폭 비트, 어울림 플래그 2개, 번호 표지, 조합 문단 번호 문자열, 글자 수·텍스트 길이).
- 스타일 동일성: DocumentCore.styles_revision — styles를 바꾸는 모든 지점(재해석, 보조 metrics 2곳, 커닝/셰이핑 컨텍스트 2곳,
  외부 대입)에서 프로세스 전역 유일 값으로 바꾸고, staged 복제본은 같은 값을 받는다. 처음 시도한 스타일 Debug 문자열 비교는
  패스마다 4.4 ms가 들어 버렸다. Debug/serde 직렬화는 완전한 동일성이 아니다(NumberingMarker Debug는 내용을 숨기고 serde는 6개 필드를
  건너뜀) — 그래서 교차 문단 입력(번호)을 명시 키로 넣었다.
- 메모는 MeasuredSection 안에 있어 측정 캐시와 같은 수명(교체·지움·문단 삽입/삭제 시 무효)을 따른다.
- 시험 전용: DocumentCore.format_memo_enabled(대조용 끄기), src/document_core/geul_incremental_tests.rs(프로파일·차등 오라클).

3. 효과(VERIFIED, native release, 같은 시험, 12회 중앙값)
