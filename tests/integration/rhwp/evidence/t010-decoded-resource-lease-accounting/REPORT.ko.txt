4. 확인한 근본 원인 (VERIFIED: 소스)
web_canvas.rs의 DECODED_CANVAS_CACHE는 BoundedCache<HtmlCanvasElement>였다.
- get은 원시 handle을 clone하고, surface_cache remove는 Release로 width/height를 0으로 만든다.
- 원시 clone은 소유권이 아니다. 그래서 캐시 퇴거가 유일한 backing 해제 지점이었다.
- job에는 decoded 소유 필드가 없었다. 비상주 임시는 그린 직후 release되어 수명이 동기 범위에만 묶였다.
- browser 이미지는 이미 Rc<ImageResource> + Weak pool이었지만, decoded는 그 구조 밖에 있었다.

5. 구현 (격리 후보; 패치 upstream-rhwp-decoded-lease-*.patch)
- surface_cache.rs(순수 Rust): Backing, DecodedLedger(checked 산술), Reservation(drop 시 해제),
  SharedBacking<B>(마지막 drop에서 1회 dispose), Release for Rc<SharedBacking>(no-op),
  BoundedCache::peek(LRU와 통계를 바꾸지 않는 조회).
- render_job.rs: DecodedLease = Rc<SharedBacking<HtmlCanvasElement>>, Job.decoded, Pool.decoded(Weak).
  job_decoded/shared_decoded/register_decoded/attach_decoded/revoke_decoded,
  MAX_NONRESIDENT_DECODED_BYTES = MAX_DECODED_BYTES(96 MiB). finish가 lease를 놓는다.
  stats에 decodedLedger를 추가했다.
- web_canvas.rs: lease 캐시, decoded_canvas 재작성(조회 순서, live backing 재제출), reserve_decode
  (헤더 크기로 할당 전 예약, 강제·회수·거절은 음성 entry 없음), decode_image_to_canvas
  (commit/실패 시 dispose, 임시 추정), draw_image·draw_image_cropped는 lease.backing()으로 그린다.
  decoded_ledger_json과 note_tree_payload를 추가했다.
- paint/resources.rs: ResourcePayloadEstimate, ResourceArena::payload_estimate.
  paint/layer_tree.rs: PageLayerTree::payload_estimate(image node, 변환 payload, RawSvg).
  wasm_api.rs: poll에서 tree payload를 관찰용으로만 기록한다(6줄).
- Geul: tests/integration/rhwp/cache-concurrency/decoded_lease_contract.rs, decoded_lease_run.py,
  decoded-lease.mjs, README 절. docs/architecture/rhwp-undo-redo.md 절. 이 증거 디렉터리.
- 기존 Rc/Weak pool 구조를 확장했고, 두 번째 lease 관리자는 만들지 않았다. 캐시 입장 정책, 한도,
  스케줄러, 알림, Full replay, 원자 게시는 바꾸지 않았다.
- 구현 중 교정 2건(실패 보존): (a) arena만 세던 tree 추정이 화학 문서에서 0이었다.
  → layer tree walker를 추가했다. (b) 시험이 1-entry 캐시를 가정했지만, SVG도 Rust decode를 먼저
  시도해 음성 entry를 남긴다는 기존 동작 때문에 기대가 틀렸다. → 시험 예산을 교정했다. 엔진 결함은 아니다.
  같은 이유로 완료 시 X가 다시 입장하는 것이 정책상 맞음을 확인했다.
  이에 따라 캐시 통계 전체를 baseline과 대조하는 검사를 추가했다.

6. 수명 비교 (VERIFIED)
- 상주 + 활성 job / 무관한 퇴거: 이전 0×0, 다음 poll 재decode → 이후 job lease가 유지, 재decode 0.
  job 종료 시 dispose되며, 정책상 재입장했으면 캐시 소유로 남고 trim(0)에서 dispose된다.
- 캐시 단독 / 퇴거: 이전·이후 모두 즉시 dispose.
- 비상주 임시 / PENDING: 이전 반환 전 0×0 → 이후 job 소유로 유지(16384 bytes 계상), 완료 시 dispose.
- job 없는 동기 그리기: 이전과 같다(그리기 직후 dispose).
- 공유 job 2개: 이후 backing 1개, 참조 2개. 한 job 취소 후 유지, 마지막 취소 시 dispose.

7. 예산과 회계 정의 (CONTRACT.ko.txt 4–5절)
decoded cache 256 MiB/256, browser cache 64 MiB/256, browser pool 256 MiB, pending 2,
resource 256, URL 32 MiB, 단일 decode 96 MiB, job 8, deadline 15 s, scratch/backup 각 64 MiB.
모두 소스에서 확인했고 늘리지 않았다. 고유 bytes(A)와 job 참조(C)는 구분한다.
비상주 D ≤ 96 MiB, 상주 B ≤ cache 예산이므로 A ≤ cache + 96 MiB(이전 엔진과 같은 상한).
- 직접 계상(추정값): decoded backing RGBA, 예약, browser unique 소유, scratch/backup.
- 관찰만 하고 강제하지 않음: decode 임시(peakDecodeTransientEstimatedBytes, 화학 문서에서 103,917,484
  관찰, 즉 단일 96 MiB RGBA 한도와 별개로 최대 약 3×RGBA), tree payload 하한
  (화학 문서 peak 2,168,706; text/geometry 제외).
- 이 카운터들은 RSS·GPU·브라우저 allocator 측정이 아니다. RSS는 INCONCLUSIVE를 유지한다.

8. 예약·정리 결과 (VERIFIED, ledger-lifecycle.json)
- 43개 ledger checkpoint(브라우저별) 모두 다음을 만족했다(runner가 재검증):
  unique=resident+nonresident, reserved=0, accountingErrors=0, nonresident ≤ 96 MiB.
  관찰 최대 nonresident는 81,120,000이다.
- 압박: 2600² PNG 4개(108,160,000 bytes)를 캐시 예산 0에서 처리했다. 1개 회수, 살아 있는 3개 =
  81,120,000 ≤ 100,663,296. 완료 후 픽셀이 같고 고유 0이다.
- cancel, close, mutation, stale target, expiry, resource error 각각 lease 해제와 예약 0을 확인했다.
  반복 terminal 5회에서 created/disposed는 불변이다. 최종 고유 0, created=disposed.
- decoded 해제는 capacity/listener 알림을 만들지 않았다(대기 대상 없음, 거짓 진행 없음).
- 거절 경로: Rust 계약으로 거절, 예약 해제, overflow 거절을 확인했다. 브라우저 job 경로에서는 회수 뒤
  단일 이미지가 96 MiB guard 안이므로 거절이 일어나지 않았다(refusedReservations=0, INFERRED 도달 불가).
  legacy 동기 API는 한도를 넘으면 unenforcedOverLimit으로 명시적으로 센다.

13. 남은 한계
- 대기 job의 비상주 lease 보유는 기회적이다. 96 MiB 압박 때는 경계에서 회수하고 다음 poll에서
  다시 decode한다. 특정 job이 준비한 자원을 끝까지 보장하는 예약은 미래 Preparing 설계 결정이다.

- 동기 poll 내부에는 취소 지점이 없다. lease 경계는 PENDING 반환과 terminal뿐이다.
