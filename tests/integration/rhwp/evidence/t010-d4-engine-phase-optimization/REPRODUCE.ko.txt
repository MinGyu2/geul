D4 engine phase / font-name classification 재현 (설치·다운로드 없음)

현재 파일은 실행 절차다. 실제 PASS/FAIL/미실행은 개별 JSON과 REPORT에서 확인한다.
공식 D4 producer/신뢰 anchor/public/gitlink/문턱은 변경하지 않는다.
ROOT는 git rev-parse --show-toplevel로 확인하고, 각 source/output은 새 경로를 쓴다.
TARGET=ROOT/target/rhwp-wasm 기존 캐시를 재사용한다. cargo clean/update/install 금지.

브라우저 비교
python3 tests/integration/rhwp/engine-phases/run.py --baseline BASELINE_CANDIDATE \
 --phase DEEP_CANDIDATE --candidate OPT_CANDIDATE --trials 8 --chrome CHROME \
 --fixtures FIXTURE_DIRECTORY --output NEW_CHROME.json
baseline/off/on/candidate4arm,11쪽×8회=88행이다. 실제 실행 순서도 기록/검증한다.
8회는 각 arm이 각 순서 위치에2번 오는 rotation/reversal이다. 첫 pass cold와 자연 warm을 구별한다.
phase-off는 비활성 span 호출의 비용, phase-on은 관찰 비용을 비교하기 위한 별도 실행물이다.
개별 측정의 exactRGBA와 final job/lease/cache cleanup을 전부 검증한다. 공식 native D4가 아니다.
WebKit은 --backend webkit --chrome tests/integration/rhwp/engine-phases/webkit-launcher.py 를 쓰고,
GEUL_D4_WEBKIT_DRIVER/GEUL_D4_XVFB를 기존 실행 파일 절대 경로로 준다. dbus-run-session 및
software rendering 환경에서 같은 page를 실제 MiniBrowser로 실행한다. WebDriver의 실제 capabilities를
로그에 남기며 unsupported --version을 제품 버전으로 꾸미지 않는다.
python3 tests/integration/rhwp/engine-phases/analyze.py --input NEW_RESULT.json --output NEW_ANALYSIS.json

별도 CPU sampling은 profile-chrome.mjs를 --chrome에 주고 GEUL_D4_CHROME/GEUL_D4_CPU_PROFILE을
설정한다. sampling500us 실행의 wall time을 무계측 성능 수치와 합치지 않는다. 함수 name/caller/self samples는
추가 원인 선택 근거이며, recursive inclusive samples를 CPU 전체의 중복 없는 합으로 부르지 않는다.
