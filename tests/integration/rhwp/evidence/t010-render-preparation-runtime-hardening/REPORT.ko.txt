2. 확인된 결함과 수정 (VERIFIED: 소스 + 수정 전/후 실제 실행)
결함: 변환 memo 예약 거부 후 잘못된 종료 분류와 불필요한 원본 decode.
경로: web_canvas::prepare_op → canvas_image_payload → render_job::memoize가 job 32MiB/모듈 64MiB 예약 확장 실패 시
mark_limit(RESOURCE_LIMIT) 후 원본 bytes로 fallback → prepare_payload가 같은 operation에서 원본을 실제 decode →
attach_decoded는 비Pending이라 lease를 붙이지 않음 → record_prepared가 lease 없음으로 mark_error → 상태가 ERROR로 덮임.
재현: 2900×2900 결정적 잡음 PNG(약 28.9MB) RealPic 워터마크 1개. 원본은 job 예약 안에 들어오지만 원본+변환 memo는 넘는다.
수정 전 후보(e88d…, Rust 1.93.1, 읽기 전용 비교): Chrome/WebKit 모두 ERROR, 준비 decodeAttempts 1(거부 뒤 decode).
수정: render_job::record_prepared는 job이 Pending이 아니면 표식 없이 false(첫 종료 사유 유지).
web_canvas::prepare_payload는 시작에서 is_preparing()이 아니면 false(거부 뒤 fallback bytes decode 금지).
수정 후(908146…): Chrome/WebKit 모두 RESOURCE_LIMIT, decodeAttempts 0, Ready/replay 0, 미게시, 정리 후 소유 0, 10/10 PASS.
같은 첫 종료 사유 유지가 revoke_decoded가 active 준비 job을 RESOURCE_LIMIT으로 끝낸 뒤 record_prepared가 ERROR로
덮던 경로도 막는다(INFERRED: 소스 추적, 그 경로 자체의 브라우저 재현은 하지 않음).
공개 poll 결과 집합, 한도, 15초 deadline, gate 기본값(off)은 바꾸지 않았다.

3. A 모델 무효화 (결함 없음, 회귀 테스트 추가)
권위 메커니즘은 둘이다. (1) HwpDocument의 DerefMut과 명시적 invalidate_render_job이 문서 Owner의 현재 job을 취소한다.
&mut self wasm export 전체를 스캔해, 필드 대입·&mut 메서드 호출은 DerefMut을 거친다는 것을 확인했다.
(2) DerefMut을 우회하는 직접 self.core 경로(bookmark 3개, hyperlink 4개)와 &self focused page-tree patch는
invalidate_page_tree_cache*/section revision으로 preparation_generation 또는 identity 필드를 바꾼다.
identity는 cache generation, document epoch, section revisions, DPI, bin_data_epoch, 출력옵션 fingerprint, fallback font를 포함한다.
font environment/exact font 등록은 DerefMut 취소로 덮인다. 문서 교체·close·같은 target 새 generation·gate 전환은 취소/Drop 경로다.
검사 지점: 준비 시작 직후, 매 PENDING 반환 전, FullReplay 진입 전, replay 후, backup 후 원자 publication 직전(기존 구현 확인).
추가 host 테스트 direct_core_mutation_paths_and_failed_mutations: 실제 bookmark/hyperlink/DPI/fallback 변경은 identity를
바꾸고, 거부된 hyperlink 편집은 바꾸지 않는다. 신원만으로 덮이지 않는 DerefMut 의존 경로는 wasm 전용이라 host에서 검사할 수 없다.
